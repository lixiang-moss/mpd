# DMEval 架构与接口（中文说明）

本文档描述 `mpd-splines-public/dmeval` 的整体架构、模块职责、接口契约与扩展方式。

> 本实现按你的要求：**只考虑串行执行**（不做复杂并行/异步）。

---
## 1. 目标与边界

### 1.1 目标

DMEval 旨在提供一个通用评估框架，用于：
- 以统一方式**编排/执行**不同规划器（或推理脚本）的实验任务（串行）。
- 从规划器输出中**提取**评估指标与配置元信息。
- 将结果**聚合**成标准化表格（CSV），并输出基础**排名**与**可视化**。

### 1.2 明确的边界（重要）

DMEval **不负责**：
- 计算轨迹指标的数值（例如 path length、smoothness、EE error、collision intensity）。
- 改变规划器的推理逻辑/采样器实现。

DMEval **只负责**：
- 运行（可选）：用子进程调用规划器脚本（例如 `python3 .../inference.py`）。
- 提取：从规划器保存的结果文件中抽取指标字段。
- 汇总：按配置分组求均值/方差，导出 CSV/排序/图。

---
## 2. 与 MPD 的对接方式（指标来源与提取路径）

以 MPD 为例：
- MPD 内部计算指标：`mpd/metrics/metrics.py`（`PlanningMetricsCalculator.compute_metrics`）
- MPD 推理脚本保存结果：`scripts/inference/inference.py`（保存 `results_single_plan-*.pt`，内部包含 `metrics`）

DMEval 的 MPD 适配器：
- 扫描结果树：查找所有 `results_single_plan-*.pt`
- 读取每个 trial 的 `args_inference.yaml`（同目录）作为配置元信息
- 从 `.pt` 中抽取（已知字段 + 可选数值字段扁平化）写入一行 trial 记录

实现文件：
- `dmeval/src/dmeval/adapters/mpd.py`

## 3. 模块划分

### 3.1 CLI 层

入口：
- `dmeval/src/dmeval/cli.py`

命令：
- `dmeval run`：串行执行 jobs 配置
- `dmeval collect`：收集并导出 CSV + 排名
- `dmeval plot`：从 `run_metrics.csv` 生成基础图（成功率/有效率/耗时，以及 time-vs-success）
- `dmeval tune`：Stage I（单场景网格调参），输出 best_configs（每个 sampler 一套）
- `dmeval compare`：Stage II（使用 best_configs 跨场景重跑对比），再做聚合与排名

### 3.2 配置加载（Config）

配置管理（Hydra，串行）：
- Stage I/II（`dmeval tune`/`dmeval compare`）使用 Hydra 的 **compose API** 来加载配置（不会改变 cwd，也不会生成 Hydra 的 `outputs/` 目录）：
  - `dmeval/src/dmeval/hydra_loader.py`
  - 支持 Hydra `defaults`（分组配置）与 `--override key=value` 覆盖。
- `dmeval run` 仍使用简单 YAML（jobs 列表）读取：
  - `dmeval/src/dmeval/config.py`

核心数据结构：
- `DMEvalConfig`：`version/results_root/defaults/jobs`
- `JobConfig`：`run_tag/cmd/seeds/workdir/env/timeout_sec`

### 3.3 执行器（Runner）

串行执行：
- `dmeval/src/dmeval/runner.py`

关键点：
- 逐个 job、逐个 seed 串行运行。
- 支持占位符替换：`{results_root}`、`{run_tag}`、`{seed}`。
- 每次执行将 stdout/stderr 写到：
  - `<results_root>/<run_tag>/<seed>/dmeval_stdout.txt`
  - `<results_root>/<run_tag>/<seed>/dmeval_stderr.txt`
- 记录执行信息写入：
  - `<results_root>/_dmeval/run_records.yaml`

### 3.4 结果适配器（Adapter）

Adapter 的职责是“面向某个规划器的结果契约”：
- 如何发现 trial 产物（文件布局/命名）
- 如何加载 trial 对象（例如 `torch.load`）
- 如何将 trial 对象映射成一行标准字段（dict）

接口定义：
- `dmeval/src/dmeval/adapters/base.py`
  - `TrialArtifact`：`results_root/run_dir/result_path/run_tag/seed/result_file`
  - `ResultsAdapter`：`discover_trials/load_trial_object/extract_row`

MPD 实现：
- `dmeval/src/dmeval/adapters/mpd.py`

### 3.5 聚合与导出（Collect）

收集 + 导出：
- `dmeval/src/dmeval/collect.py`

输出：
1) `trial_metrics.csv`：每个 `results_single_plan-*.pt` 一行（trial 级）
2) `run_metrics.csv`：按 `(scenario, run_tag, seed)` 分组，对数值列求 mean/std（run 级）
3) `rank_*.csv`：基于 `run_metrics.csv` 的 mean 字段排序（更适合公平对比）

### 3.6 可视化（Plot）

绘图：
- `dmeval/src/dmeval/plot.py`

当前默认图（每个 scenario 一组）：
- `bar_success.png`
- `bar_fraction_valid.png`
- `bar_time.png`
- `scatter_time_vs_success.png`

后续可扩展方向：
- 基于 `trial_metrics.csv` 做箱线图/分位数统计
- trade-off 曲线（time vs quality）
- 超参热力图（两个超参 → 指标）

## 4. 输入/输出契约（建议你后续固化）

### 4.1 结果目录结构（推荐）

推荐布局与 MPD sweep 脚本一致：
```
<results_root>/
  <run_tag>/
    <seed>/
      args_inference.yaml
      results_single_plan-000.pt
      results_single_plan-001.pt
      ...
```

说明：
- `run_tag`：用于区分 sampler/超参组合
- `seed`：用于区分重复 runs（或者随机性控制）

### 4.2 `args_inference.yaml`

用于记录“配置元信息”（例如 `planner_alg/diffusion_sampling_method/env_id_replace/...`）。

DMEval 支持两种模式：
- 默认：只抽取少数关键配置字段（保持表宽可控）
- `--include_all_config`：把整个 YAML 扁平化写入 CSV（字段很多，但便于后期分析）

### 4.3 `.pt` 结果文件

对 MPD 来说，`.pt` 内含：
- `t_inference_total/t_generator/t_guide`
- `metrics`（DotMap），典型分组：`trajs_all/trajs_valid/trajs_best`

DMEval 会抽取一组“已知关键字段”，并且可选地把所有数值字段扁平化加入（避免未来 MPD 新增指标漏采）。

## 5. Docker 环境依赖建议

DMEval 核心依赖（最低）：
- `python>=3.8`
- `pip`
- `PyYAML`
- `hydra-core`（用于配置管理；安装 dmeval 时会一并安装）

如果你要 `dmeval collect` 读取 MPD `.pt`：
- `torch`
- `dotmap`

如果你要 `dmeval plot`：
- `matplotlib`

安装方式（在 `mpd-splines-public/` 目录下）：
```bash
python -m pip install -e dmeval
python -m pip install -e "dmeval[mpd]"
python -m pip install -e "dmeval[plot]"
```

（可选）示例：用 Hydra override 覆盖参数（仍然串行执行）：
```bash
dmeval tune --config mpd-splines-public/dmeval/configs/example_mpd_tune.yaml \
  --override scenario=warehouse \
  --override common_inference_args.n_start_goal_states=20
```

## 6. 你需要补充/确认的需求点（我建议尽早定）

### 6.1 Stage I（调参）目标函数与约束

proposal 中提到“阈值 + 优化”范式，但目前未固化：
- feasibility threshold：`success_mean >= ?` / `fraction_valid_mean >= ?`
- 在满足阈值后：优先最短时间？还是时间-质量复合评分？

建议你明确：
- 约束阈值（按场景是否不同）
- 复合评分公式（可配置）

### 6.2 Stage II（公平比较）统计口径

例如：
- 以 run 级均值比较，还是以 trial 分布比较（箱线图）？
- 多场景时是否要做宏平均/加权平均？

### 6.3 可视化清单

你希望最终论文/报告里固定输出哪些图：
- success / validity 的柱状图或箱线图
- time vs quality trade-off 曲线
- 超参热力图（如 steps×order → success/time）

## 7. 扩展：新增一个规划器 Adapter 的最小步骤

1) 新建 `dmeval/src/dmeval/adapters/<planner>.py`
2) 实现：
   - `discover_trials(results_root)`：发现每个 trial 的结果文件
   - `load_trial_object(artifact)`：加载结果对象（json/yaml/pt/npz 都可）
   - `extract_row(...)`：抽取一行 dict（尽量稳定字段 + 可选动态字段）
3) 在 `dmeval/src/dmeval/collect.py` 中注册该 adapter 名称
